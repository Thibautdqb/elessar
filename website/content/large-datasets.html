Guide / Inputs and sampling

Profile files and understand what is sampled.

elessar.see() and elessar.load() accept file paths and tabular objects. Large-data support combines progressive typing, streaming summaries and sampled statistical analyses.

Supported inputs

InputExamples
In-memory objectspandas DataFrame/Series, Polars DataFrame/LazyFrame, PyArrow Table, Dask DataFrame, NumPy array, dicts and lists of records.
Delimited textCSV, TSV and other delimited files, with delimiter and encoding inference.
Columnar formatsParquet, Feather/Arrow and ORC.
SpreadsheetsExcel and OpenDocument; select a sheet with sheet=.
Other formatsJSON/JSONL, SQLite, SAS, Stata, SPSS, HDF5, XML and supported local pickle files. Some formats may need an additional format-specific dependency.
Collections and remote sourcesGlob patterns, folders and URLs. Use supported files and review loading options for the format.

Read a file without running the analysis

import elessar

source = elessar.load("export.xlsx", sheet="2024")
print(source.df.head())
print(source.origin)

source.df holds the loaded rows, or the profile sample for a large source. source.full holds full-pass summaries when that loading mode applies.

Control the work on a large CSV

config = elessar.StoneConfig(
    max_rows=100_000,
    sample_size=20_000,
    fit_sample_size=10_000,
    random_state=42,
)

report = elessar.see(
    "large.csv",
    config=config,
    engine="pandas",
    open_report=False,
)
print(report.overview)

engine="pandas" selects single-process streaming for supported streamed inputs. The default engine="auto" can use Dask for large text files. Streaming strategy depends on the source format and available memory; a compressed or spreadsheet source does not necessarily behave like a plain CSV.

Separate full-pass counts from sample estimates

  • max_rows limits rows used for the large-table profile; its default is 1,000,000.
  • sample_size limits costly analyses such as correlations and pairwise tests; its default is 100,000.
  • fit_sample_size limits distribution fitting and normality tests; its default is 20,000.
  • In streamed mode, full-pass summaries provide counts and supported descriptive figures over every row. Consult report.overview and report.full for the actual run.
  • Exact duplicate counting can be skipped when its memory budget is exceeded; the report records this. Treat any omitted statistic as unavailable.
  • Sampling is deterministic for a fixed random_state. Time-series handling preserves time structure rather than treating scattered rows as a complete series.

Large-data support is not a claim that every statistic is exact or that arbitrary file sizes fit in memory. Check the run details, the sampled row count and any recorded errors before using results.

For a deliberate first-rows preview, nrows= limits the rows read; those results describe the limited input. For format-specific details, see the package README.
